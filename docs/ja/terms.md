# 用語解説（利用者向け）

画面に出てくる専門用語と略語を、ISMS・Pマークの担当者向けに解説します。サイドバーの並びに沿って説明しています。

規格の本文は引用していません。規格の要求事項は、JIS Q 27001・JIS Q 15001 などの原文で確認してください。翻訳者向けの訳語表は [glossary.md](glossary.md) にあります。

## サイドバーの略語

| 表示 | 正式名 | 意味 |
| --- | --- | --- |
| TPRM | Third-Party Risk Management（取引先リスク管理） | 委託先・仕入先など社外の組織に関するリスクを管理する機能 |
| CMP | Consent Management Platform（Cookie同意管理） | Web サイトの Cookie バナーと訪問者の同意を管理する機能 |
| IT資産管理 | IT Asset Management（ITAM） | 従業員の PC などの端末を管理する機能 |

## ガバナンス

ISMS の運用の中心となる機能です。

| 用語 | 解説 |
| --- | --- |
| フレームワーク | ISO 27001、SOC 2 など、準拠を目指す規格や基準。取り込むと、その規格の管理策が一覧になります。独自のフレームワークも作れます |
| 管理策 | フレームワーク側の要求項目。ISO 27001 の附属書 A の各項目がこれにあたります |
| 内部統制 | 自社が実際に行う統制。1 つの内部統制を複数のフレームワークの管理策に紐付けられるので、ISO 27001 と SOC 2 を同時に運用するときに重複を減らせます |
| 適用宣言書（SoA） | Statement of Applicability。管理策ごとに、適用するか除外するかと、その理由をまとめた文書。ISMS 認証の審査で提出を求められます |
| 監査 | 内部監査や認証審査の記録。監査ごとに対象のフレームワーク、期間、状態を管理します |
| 指摘事項 | 監査や日々の運用で見つかった問題。不適合、観察事項などを記録し、是正処置まで追跡します |
| 是正処置 | 不適合の原因を取り除き、再発を防ぐための処置 |
| 証跡 | 内部統制が実施されていることを示す記録（スクリーンショット、ログ、ファイル、URL など）。審査で提示します |
| ドキュメント | 方針、手順、計画、台帳、記録などの文書。版の管理、承認、従業員の署名に対応しています |
| タスク | 担当者と期限を付けて管理する作業 |

### フレームワークを日本語で取り込む

画面の「フレームワーク」から一覧の規格を選ぶと、英語の見出しで取り込まれます。ISO 27001:2022 は日本語版のファイルを用意しています（見出しは英語版をもとに独自に作成したもので、JIS Q 27001 の本文からの転載ではありません）。

1. [ISO27001-2022.json（日本語版）](../../apps/console/public/data/frameworks/ja-JP/ISO27001-2022.json) をダウンロードします。
2. 英語版をすでに取り込んでいる場合は削除します。同じ規格は 1 つしか取り込めないためです。削除すると、英語版の管理策との紐付け（内部統制・適用宣言書）も消えます。
3. 「フレームワーク」画面のファイル取り込みから、ダウンロードしたファイルを選びます。

## リスク管理

| 用語 | 解説 |
| --- | --- |
| リスクアセスメント | リスクを洗い出し、分析し、評価する一連の作業 |
| リスク分析 | 業務の流れや情報の流れを図にして、脅威とシナリオからリスクを洗い出す機能 |
| 発生可能性・影響度 | リスクの大きさを決める 2 つの軸。この 2 つを掛け合わせてリスクの大きさを評価します |
| 固有リスク | 対策をとる前のリスクの大きさ |
| 残留リスク | 対策をとった後に残るリスクの大きさ |
| リスク対応 | リスクへの対処方法。低減（対策で小さくする）、受容（そのまま受け入れる）、回避（原因となる活動をやめる）、移転（保険や委託で他者に移す）の 4 つがあります |
| リスク対応計画 | リスクを低減するために、どの内部統制をいつまでに実施するかの計画 |
| リスクオーナー | そのリスクの管理に責任と権限を持つ人 |

## TPRM（取引先リスク管理）

| 用語 | 解説 |
| --- | --- |
| 取引先 | 委託先、仕入先、クラウドサービスなど社外の組織。Pマークの「委託先の監督」や ISMS の供給者管理の対象です |
| リスクアセスメント（取引先） | 取引先ごとに、扱うデータの機微度や事業への影響度からリスクを評価します |
| 保証 | 取引先が取得している認証や公開している報告書（ISO 27001 認証書、SOC 2 報告書など） |
| SOC 2 | 米国公認会計士協会（AICPA）の基準に基づく、委託先の内部統制に関する保証報告書 |
| データ処理契約（DPA） | Data Processing Agreement。個人データの取扱いを委託するときに結ぶ契約。日本では「個人情報の取扱いに関する覚書」などに相当します |
| 事業提携契約（BAA） | Business Associate Agreement。米国 HIPAA（医療情報の保護に関する法律）で求められる契約。日本の組織ではほとんど使いません |
| サプライチェーン | 取引先がさらに利用している再委託先などの連なり |

## プライバシー

| 用語 | 解説 |
| --- | --- |
| 処理活動 | 個人データを扱う業務の単位（採用、給与計算、顧客管理など）。目的、扱うデータ、保存期間、委託先をまとめて記録します。Pマークの「個人情報の特定」で作る台帳に近いものです |
| 本人からの請求 | 本人（個人データの持ち主）から受けた開示、訂正、削除などの請求。受付から回答までを記録します。Pマークの「開示等の請求等」への対応に使えます |
| データ保護影響評価（DPIA） | Data Protection Impact Assessment。リスクの高い個人データの取扱いを始める前に、プライバシーへの影響を評価すること。EU の GDPR で義務付けられています。日本では JIS X 9251 の「プライバシー影響評価（PIA）」が近い考え方です |
| 移転影響評価（TIA） | Transfer Impact Assessment。個人データを EU 域外へ移すときに、移転先の国の法制度でデータが十分に守られるかを評価すること。GDPR の対応で使います |
| 法的根拠 | 個人データを扱ってよい根拠（同意、契約の履行、法令上の義務など）。GDPR の考え方です |
| 標準契約条項（SCC） | EU 域外へ個人データを移すときに使う、欧州委員会が定めたひな形の契約条項 |

## CMP（Cookie同意管理）

| 用語 | 解説 |
| --- | --- |
| Cookie バナー | Web サイトを訪れた人に Cookie の利用目的を知らせ、同意を得るための表示 |
| トラッカー | Cookie やローカルストレージなど、訪問者の情報を保存・追跡する仕組み |
| 同意履歴 | 訪問者がいつ、どの目的に同意・拒否したかの記録 |
| TCF | Transparency & Consent Framework。広告業界団体 IAB Europe が定めた、広告目的の同意を広告事業者間で受け渡すための共通規格。EU 向けに広告を配信するサイトで使います |
| IAB | Interactive Advertising Bureau。オンライン広告の業界団体 |
| ベンダーリスト（GVL） | Global Vendor List。TCF に登録された広告事業者の一覧 |
| CMP ID | TCF で、同意管理ツールに割り当てられる登録番号 |
| GPC（拒否シグナル） | Global Privacy Control。ブラウザが「個人データの販売や共有を望まない」と自動で伝える仕組み |

## 台帳

| 用語 | 解説 |
| --- | --- |
| データ | 組織が扱う情報の種類（顧客情報、従業員情報など）と、その機密区分 |
| 資産 | 情報資産。システム、サービス、機器など。ISMS の情報資産台帳にあたります |
| 業務機能 | 事業を構成する業務。停止したときの影響を評価し、事業継続計画（BCP）に使います |
| 最大許容停止時間（MTD） | Maximum Tolerable Downtime。業務が止まっても事業が耐えられる最大の時間 |
| 目標復旧時間（RTO） | Recovery Time Objective。停止した業務をどれだけの時間で復旧させるかの目標 |
| 目標復旧時点（RPO） | Recovery Point Objective。障害時に、どの時点までのデータを復旧できればよいかの目標。たとえば RPO が 24 時間なら、最大 1 日分のデータ消失を許容します |
| AIシステム | 組織が開発・利用する AI。EU AI 法のリスク区分（高リスク、限定リスク、最小リスク、汎用 AI）で分類します |
| 汎用AI（GPAI） | General-Purpose AI。大規模言語モデルのように、さまざまな用途に使える AI |
| 提供者・導入者 | EU AI 法での役割。提供者は AI を開発して市場に出す側、導入者は業務で使う側 |
| 義務 | 法令や契約から生じる、組織が守るべき事項。遵守状況（遵守・一部遵守・未遵守）を管理します |

## アクセスレビュー

| 用語 | 解説 |
| --- | --- |
| アクセスレビュー | 各システムのアカウントと権限が適切かを定期的に棚卸しすること |
| キャンペーン | 1 回分のアクセスレビューの実施単位 |
| ソース | レビュー対象のアカウント一覧の取得元（Google Workspace、Microsoft 365、CSV など） |
| 職務分掌の競合 | 1 人に、本来は分けるべき権限（申請と承認など）が集まっている状態 |
| 多要素認証（MFA） | パスワードに加えて、スマートフォンなど別の要素でも本人確認する方式 |

## 設定

| 用語 | 解説 |
| --- | --- |
| 組織の状況 | 組織の事業内容、利害関係者、ISMS の適用範囲などの前提情報 |
| ID・アクセス管理（IAM） | Identity and Access Management。このツールにログインできるユーザーと権限の管理 |
| SAML SSO | 社内の ID 基盤（Microsoft Entra ID、Okta、Google Workspace など）のアカウントでログインできるようにする仕組み |
| IdP | Identity Provider。SAML SSO でログインを担う社内の ID 基盤 |
| SCIM | ID 基盤のユーザーの追加・削除を、このツールに自動で反映する仕組み |
| 監査ログ | このツールで誰がいつ何をしたかの記録 |
| Webhook | このツールで起きた出来事を、外部のシステムへ自動で通知する仕組み |
| コネクター | 外部サービスと接続して、データや証跡を取り込むための設定 |
